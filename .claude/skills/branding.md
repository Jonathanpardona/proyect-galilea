# Skill de Branding — Proyecto Galilea

## Contexto del proyecto
Este proyecto es una plataforma de gestión para un centro médico/clínica ubicado en el **sector Galilea**.
- **"Galilea"** es el nombre del sector geográfico, NO el nombre del centro médico.
- El nombre del centro médico **aún está por definir**.
- El branding debe reflejar:
  - **Confianza y profesionalismo** médico
  - **Calidez humana** hacia pacientes
  - **Modernidad y tecnología** accesible

## Identidad de marca

### Nombre del centro médico — en evaluación
El cliente está decidiendo entre propuestas con estilo moderno y profesional. Candidatos actuales:

| Opción | Concepto |
|--------|----------|
| **Nexasalud** | "Nexa" = conexión/vínculo. Transmite red de salud, integración, tecnología conectada |
| **Novamedic** | "Nova" = nuevo/innovación. Transmite medicina de vanguardia, renovación, modernidad |

**Criterios para elegir el nombre definitivo:**
- Fácil de pronunciar y recordar
- Funciona bien como marca digital (dominio, redes sociales)
- Transmite confianza médica + modernidad
- Se diferencia de clínicas tradicionales del sector

> Hasta que se defina el nombre, usar el placeholder `[Nombre Centro Médico]` en cualquier texto de UI o documentación.

### Tipografía
- **Títulos:** Inter o Montserrat (Bold) — moderno y legible
- **Cuerpo:** Inter Regular — limpio para lectura de datos clínicos
- **Datos/números:** Monospace (JetBrains Mono) — para tablas y métricas

### Tono de comunicación
- Claro y directo (sin jerga médica innecesaria)
- Empático con el paciente
- Técnico y preciso con el equipo médico

## Asesoría de Marketing

### Segmentos objetivo
1. **Pacientes** — personas que buscan atención de calidad cercana
2. **Médicos/profesionales** — que necesitan herramientas eficientes
3. **Administración clínica** — que gestiona citas, asistencia y reportes

### Métricas clave de seguimiento
- Tasa de asistencia a citas (% presentes vs agendados)
- Tasa de cancelación y no-show
- Retención de pacientes (visitas recurrentes)
- Satisfacción post-consulta

## Cruce de datos para verificar asistencia

Cuando el usuario pida analizar datos de asistencia, seguir este protocolo:

1. **Identificar** las fuentes de datos disponibles (citas agendadas, registros de llegada)
2. **Calcular** métricas:
   - `Tasa asistencia = (asistidos / agendados) × 100`
   - `No-show rate = (ausentes / agendados) × 100`
   - `Cancelaciones tardías = cancelaciones < 24h antes`
3. **Segmentar** por: doctor, especialidad, día de semana, franja horaria
4. **Recomendar** acciones basadas en patrones (ej: recordatorios automáticos si no-show > 20%)
